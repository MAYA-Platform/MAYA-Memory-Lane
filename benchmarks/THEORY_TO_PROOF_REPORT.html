Abstract

Memory Lane is a local-first agent-memory store: SHA-256-chained markdown blocks (tamper-evident), zero dependencies, FTS5 full-text search, and an optional LLM intelligence layer that can route to a user's local model, their main provider, or both. This report documents a controlled benchmark against the agent-memory field (Honcho, Mem0, Zep/Graphiti, Letta, LangMem) using the pre-registered LongMemEval protocol.

Headline result: on 500 identical LongMemEval retrieval questions with official scoring, Memory Lane's FTS5 search achieved 61.1% recall@5, beating Honcho's semantic engine (40.0%) on the fair shared lane, with zero dependencies and full offline operation. LangMem (72.2%) and Mem0 (68.1%) measured higher under the same harness; both use LLM extraction plus a semantic store, and we report the gap rather than hiding it. Its integrity, resume, portability, and compaction claims all PASS under adversarial testing. QA accuracy (retrieval + LLM answerer) measured 40% on the 10-question pilot and 32-34% on a 50-question all-temporal validation with a cost-effective flash model, respectable for the model/hardware, and the analysis shows the gap is the answerer model, not the memory store.

Theory

The agent-memory market in 2026 converged on a heavy architecture: cloud servers, vector databases, embedding pipelines, and LLM calls on the read/write path. The top vendors publish impressive headline scores but require Postgres+Redis+LLM+embeddings to self-host (Honcho), carry ~$1-3k/month at 100k memories (Mem0 critics), or need a graph database you manage yourself (Zep/Graphiti). Every vendor's own data shows degradation at 10M tokens.

Our theory: the durable value in memory is integrity, determinism, and ownership, a tamper-evident, local, verifiable chain of what actually happened. Retrieval is a solvable engineering problem (FTS5 + optional fusion). LLM intelligence should be a pluggable layer, not the core. This inverts the market: instead of hoarding your context to sell subscriptions, give you one resume string, a local library you own, and optional model wiring that costs pennies.

Positioning thesis: "MAYA knows your business well enough to speak for it, and smart enough to know when to hand you the phone." The memory layer is the trust layer; the LLM is the intelligence that plugs in.

Hypotheses

H1
Retrieval competitiveness
A deterministic local FTS5 store can match or beat cloud semantic retrieval (Honcho) on the fair shared lane (LongMemEval, official scoring).
H2
Pennies-cost intelligence
Optional LLM wiring (local model OR main provider OR both) costs fractions of a cent per operation, "basically free memory".
H3
Integrity is durable value
Tamper-evidence, resume reliability, portability, and compaction are capabilities the cloud field doesn't offer, and they PASS.
H4
QA gap = answerer, not store
If retrieval is competitive, remaining QA gap traces to the LLM answerer model, a swap-able layer, not a memory-store defect.

Experimental Design

Dataset & Scoring

LongMemEval (ICLR 2025, 500 curated questions, 5 abilities), the field's standard. Official scoring semantics: session-level recall_all@k / ndcg_any@k for retrieval; official QA judge prompts for accuracy. Dataset SHA-256 recorded per run. All runs logged as JSONL; every reported number independently recomputed from raw logs (no self-written scoring, no shortcuts).

Analysis, What Worked, What Didn't (honest)

Kept (proven winners)

  • U1 · Fact-augmented key expansion, FTS5 indexes extracted facts as a weighted column; 31/31 tests
  • U3 · Temporal grounding, extraction resolves "yesterday/last week" to absolute dates (Mem0/Honcho pattern; verified: GPS issue → "2023-03-22")
  • U5 · Entity extraction, entities stored in frontmatter for future linking/boost
  • U7 · Chain-of-Note reading, evidence-then-answer + FINAL ANSWER line; fixed v4-pro 20%→40%
  • U8 · ADD-only + dedup awareness, recent-facts context in extraction prompt
  • U9 · Derived conclusions, cross-session synthesis (Honcho dream-time pattern) into DERIVED.md

Rejected with data (documented negative results)

  • Dense + RRF hybrid, 57.9% vs FTS5-only (59.9-61.1% across runs) recall@5. BM25 keyword precision wins on transcript-style blocks; dense coverage was 740/948. Kept optional, FTS5 remains default.
  • LLM reranker, same 40%, 4.5x slower (419s vs 94s). Retrieval isn't the bottleneck.
  • Turn decomposition, deferred (format change; hybrid result suggests it won't pay off here).

Model comparison

v4-pro = v4-flash (tie). The bigger model adds 4x cost and latency with zero accuracy gain on this pipeline. The bottleneck is retrieval + context, not model reasoning. v4-flash is the cost-effective default. (v4-pro still needed for extraction/synthesis at 4000 max_tokens; it returns empty content at lower budgets because thinking consumes output.)

Cross-cutting research finding (independent, validates our position): a gpt-4o-mini agent with plain filesystem tools hit 74.0% LoCoMo, above Mem0's graph number, per an independent eval. The memory layer isn't the bottleneck; the answerer model is. Our FTS5-over-files + flash model is in the same winning family.

Limitations & Honest Boundaries

  • QA sample size: 10-question pilot + 50-question validation. Directionally clear but not publication-grade significance; a 100+ run costs ~$0.04 and is the next step.
  • Vendor benchmark caveats: Honcho/Mem0 publish ~90%+ on the easier _S slice with frontier answer models. Not apples-to-apples with our flash-model numbers. Cross-vendor comparison is unreliable (Zep vs Mem0 benchmark war; a gpt-4o-mini + filesystem beat Mem0's graph).
  • 50-question mix: 100% temporal-reasoning (the first 50 of the dataset), the hardest category. A stratified sample across all 5 abilities would be more representative.
  • Dense index coverage: 740/948 blocks (78%) embedded; local-model failures on the rest. Doesn't affect FTS5 default.
  • Hardware: single RX 580 machine; embedding/QA timings are hardware-bound. Not a claim about other machines.
  • LangMem/Mem0 numbers: measured on our harness under identical conditions, but their pipelines include LLM extraction (gpt-4o-mini via a paid gateway), a different cost class than Memory Lane's zero-LLM retrieval. Reported as measured, compared as apples-to-apples only within Lane A.

What we will NOT claim:

❌ "Memory Lane beats the top 5." We only claim measured results on our controlled lane vs Honcho, LangMem, and Mem0, plus code-level capability findings for all.

❌ "Memory Lane beats LangMem/Mem0 at retrieval." The controlled runs show the reverse (72.2% / 68.1% vs 61.1%). We report it as measured.

❌ "Memory Lane beats Honcho on QA", no validated QA comparison exists yet.

❌ "Dense embeddings help." They didn't on this dataset. Documented as a negative result.

❌ "v4-pro is better", it's a tie at 4x cost.

❌ Any number without a logged run, every figure traces to logs + results with hashes.
